3  ANOVA and other tests on the LM

NoteIn this chapter

In this chapter, you will learn

  • that an ANOVA is a test on top of a regression model, how it measures and tests the improvement of model fit, and how to partition the model into custom blocks (Section 3.1, Section 3.2.2, Section 3.1.2);
  • why the order of the predictors matters for collinear predictors, and how to choose between type I, II and III ANOVA (Section 3.2.3, Section 3.2.3.2);
  • why contrast coding and centering change type III results for terms in interactions, and how emmeans gives results that do not depend on the coding, including simple effects (Section 3.2.4, Note 3.1);
  • why raw variance fractions are too high for terms with many df (Section 3.2.5).

Workflow steps (Section 1.1.2): step 3 (coding of factors), step 6 (tests on the fitted model).

Prerequisites: the linear model and its handling of categorical predictors (Chapter 2, Section 2.6).

3.1 The idea of ANOVA

ANOVA stands for ANalysis Of VAriance. The basic idea is to find out how much of the signal (variance) is explained by different factors. We had already briefly introduced ANOVA in the section on ANOVA (Section 2.6.2) in the chapter on linear regression.

The problem with explaining ANOVA is that the term is fraught with historical meanings and explanations that are no longer relevant. It used to be that ANOVA is a stand-alone method that you use for experimental designs with different treatments, that ANOVA assumes normal distribution and partitions sum of squares, that there are repeated-measure ANOVAs and all that, and those varieties of ANOVA partly still exist, but in general, there is a much simpler and general explanation of ANOVA:

Modern explanation: ANOVA is not a statistical model, but a hypothesis test that can be performed on top of any regression model. What this test is doing is to measure how much model fit improves when a predictor is added, and if this improvement is significant.

We use anova(), the general R function for comparing models (its use for GLMs and mixed models is discussed in the respective chapters); aov() is mainly needed as input for post-hoc tests such as TukeyHSD() (see Section 2.6.3).

In the standard ANOVA for the LM, model fit is measured by the reduction in residual sum of squares. Let’s look at the example above. In the ANOVA table above, we (virtually) start with an intercept only model. Now, what the table tells us is that adding Wind to the model reduces the Sum Sq. by 45284, and adding also Temp reduces the Sum Sq by another 25886, which leaves us with 53973 residual sum sq. From this, we can also conclude that the total sum of squares of the response is 53973 + 25886 + 45284 = 125143. Let’s check this:

sum((fit$model$Ozone - mean(fit$model$Ozone))^2)
[1] 125143.1

Thus, we can compute the fraction of variance attributed to each model component and to the residuals (note the last entry is the unexplained remainder, not an explained component):

totalSumSq = 45284 + 25886 + 53973 # total sum of squares
45284/totalSumSq # R2 Wind
[1] 0.361858
25886/totalSumSq # R2 Temp
[1] 0.2068514
53973/totalSumSq # unexplained fraction (residual)
[1] 0.4312906

Moreover, the ANOVA table performs tests to see if the improvement of model fit is significant, compared to the model without the respective term. This is important because adding a predictor always improves model fit, even if it has no effect (we will discuss this in more detail in the chapter on model selection, in particular Section 8.2.1).

To interpret the p-values, consider that H0 = the simpler model is true, thus we test if the improvement of model fit is higher than what we would expect if the predictor has no effect.

3.1.2 Customizing the partitioning

An important thing to note is that in an ANOVA, you don’t need to always separate one predictor after the other, you can also work in blocks of predictors, or entire components of the model.

There are a number of cases where this makes a lot of sense. A typical example is, if you are fitting a polynomial of a predictor. Consider, for example, the following regression:

fit = lm(Ozone ~ Wind + I(Wind^2) + Temp + I(Temp^2), data = airquality)

Maybe, we would like to ask how much variance is explained by Wind + Wind^2, and how much by Temp + Temp^2. In this case, we can perform custom ANOVA, using the anova() function that you may have seen in the solution of the exercise in Section 2.5.2, to compare models via a likelihood ratio test (LRT).

m0 = lm(Ozone ~ 1, data = airquality)
m1 = lm(Ozone ~ Wind + I(Wind^2) , data = airquality)
m2 = lm(Ozone ~ Wind + I(Wind^2) + Temp + I(Temp^2), data = airquality)
anova(m0, m1, m2)

3.2 Fundamental issues in ANOVA

There are five basic problems that we will come back again when generalizing this principle across a range of models:

  1. How should we measure “improvement of model fit”. Traditionally, improvement is measured by the reduction of the residual sum of squares, but for GLMs, we will have to expand this definition
  2. How should we test if the improvement in fit is significant? For simple models, this is not so much a problem
  3. How should we partition variance if predictors are collinear, and thus the order in which predictors are included matters
  4. Related to the previous point, for categorical predictors, the choice of contrasts changes the results of the type III ANOVA (see Section 3.2.4).
  5. Should we correct for complexity?

Let’s look at the problem one by one:

3.2.1 Measuring model fit

The definition of model fit via sum of squares makes sense as long as we work with linear models.

For GLMs, this definition doesn’t make sense any more. A number of so-called pseudo-R2 metrics have been proposed. Most of them are based on the likelihood (as a measure of model fit) and try to recover as far as possible the properties of an R2 for the linear model.

A common metric is McFadden pseudo-R2, which is defined as 1-[LogL(M)/LogL(M0)], where M is our model, and M0 is an intercept only model. However, many other definitions of “importance” are possible, and in the broadest sense, you could say the principle of ANOVA is to separate out the importance of different predictors or model components, however this importance is measured.

3.2.2 Testing if the improvement is significant

The test used in our example before is an F-test. The F-test is used for models that assume normal distribution. The F-test can be interpreted as a special case of a likelihood ratio test (LRT, for the reason see Tip 3.1), which you may have seen in the solution of the exercise in Section 2.5.2; more on LRTs in the section on likelihood-ratio tests (Section 8.2.1). An LRT compares two nested models, M0 (simpler) and M1:

  1. H0: M0 is true
  2. Test statistic: \(-2 \log \frac{L(M_0)}{L(M_1)} = -2 \left[\log L(M_0) - \log L(M_1)\right]\), i.e. minus twice the difference in maximized log-likelihoods
  3. Under H0 and relatively broad regularity conditions, the test statistic is asymptotically chi-squared distributed, with df = difference in the number of free parameters of the models M1, M0
Tip 3.1: Why the F-test is a likelihood ratio test

The general principle behind both tests is the likelihood ratio test, explained in the section on likelihood-ratio tests (Section 8.2.1). For a linear model with normal residuals, the maximized log-likelihood depends on the data only through the residual sum of squares, \(\log L = -\frac{n}{2} \log(RSS/n) + \text{const}\). The LRT statistic for two nested models is therefore

\[-2 \log \frac{L(M_0)}{L(M_1)} = n \log \frac{RSS_0}{RSS_1} = n \log \left(1 + \frac{q \, F}{n - p_1}\right) \quad \text{with} \quad F = \frac{(RSS_0 - RSS_1)/q}{RSS_1/(n - p_1)},\]

where \(q\) is the number of additional parameters in M1 and \(p_1\) the number of regression coefficients of M1. The LRT statistic is a monotone function of F, so both tests rank all possible results in the same way: the F-test is an LRT. They differ only in the reference distribution. The chi-squared distribution of the LRT is a large-sample approximation, while the F distribution is exact for linear models with normal residuals, because it accounts for the fact that the residual variance is estimated. This is why anova() uses the F-test for lm, and the chi-squared LRT for GLMs and mixed models, for which no exact distribution exists. For nonlinear least squares (Chapter 5), anova() also reports an F-test, but there both distributions are approximations.

datCC = airquality[complete.cases(airquality), ]
mF0 = lm(Ozone ~ Temp, data = datCC)
mF1 = lm(Ozone ~ Temp + Wind, data = datCC)
anova(mF0, mF1) # F-test

This setup works for LMs and GLMs, but runs into problems when the definition how many df a model has is unclear. This is in particular the case for mixed models. In this case, one can resort to simulated LRTs. Simulated LRTs are a special case of the bootstrap (see the section on nonparametrics and the bootstrap, Section 2.12, in particular Section 2.12.2). More precisely, they are a parametric bootstrap: instead of assuming that the test statistic follows a chi-squared distribution (point 3 above), we generate its distribution under H0 by simulating new data from the fitted model M0. Because this method is crucial for mixed models, I want to shortly explain it already here:

  1. Simulate data from H0 (= the fitted model M0)
  2. Re-fit M0 and M1, and calculate likelihood ratios
  3. Repeat n times to get an idea about the expected increase in likelihood when moving to M1 under the assumption that M0 is correct
library(DHARMa)
m0 = lm(Ozone ~ Wind , data = airquality)
m1 = lm(Ozone ~ Wind + Temp, data = airquality)
simulateLRT(m0, m1)

3.2.3 Collinearity means that order matters

Another key problem in ANOVA, and a source of much confusion, is how to deal with the fact that often, the order in which model components are added matters. Compare the results of our previous ANOVA with this one, where I only flipped the order of Temp and Wind:

m1 = lm(Ozone ~ Wind + Temp, data = airquality)
m2 = lm(Ozone ~ Temp + Wind, data = airquality)

The result is markedly different, and the reason is that anova() (like aov()) performs a so-called type I ANOVA. The type I ANOVA adds variables in the order in which they are in the model formula, and because Temp and Wind are collinear, the variable that is added first to the model will absorb variation from the other, and thus seems to explain more of the response.

There are other types of ANOVA that avoid this problem. The so-called type II ANOVA shows for each variable only the part that is uniquely attributable to the respective variable. This is done by discarding the R2 part that is shared by the two predictors due to collinearity (see Figure 3.1 below)

Why is there an (Intercept) row in type III, but not in type II? Type II respects the hierarchy of the model (marginality principle): a term is only tested in models without the terms that build on it, e.g. a main effect A is tested without the interaction A:B. As all terms build on the intercept, the intercept is never tested. Type III, by design, does not follow this hierarchy and tests every term given all others: for the intercept, whether the prediction is zero at Wind = 0 and Temp = 0 (rarely of interest), and for main effects in models with interactions, a hypothesis that depends on centering and coding.

In this model without interaction, type III is identical to type II. Differences only arise for terms that are part of an interaction, as shown in Caution 3.1.

Caution 3.1: Type III ANOVA and centering of numeric predictors

In a model with an interaction x1 * x2, the main effect of x1 describes the effect of x1 at x2 = 0 (see Section 3.2.4.2, Section 2.10.3 and Schielzeth (2010)). The type III ANOVA tests exactly this. If x2 is uncentered, x2 = 0 may be far outside the data (e.g. Wind = 0 mph), and the type III test of x1 then asks a question you are probably not interested in. Centering x2 moves this point to the mean of x2. Type II, in contrast, is not affected by centering:

fit = lm(Ozone ~ scale(Temp) * scale(Wind), data = airquality)
fit2 = lm(Ozone ~ Temp * Wind, data = airquality)

In short: if you run a type III ANOVA on a model with interactions, center all numeric predictors that are part of an interaction, so that main effects are tested at a sensible point (instead of the mean, you can also subtract another value that is meaningful for your question, e.g. a reference temperature; for strongly skewed predictors, the mean may be an atypical value, and the median or a biologically meaningful value is often better). Alternatively, use emmeans::joint_tests(), which needs no centering (see Note 3.1); for the general recommendations, see Section 3.2.3.2.

Polynomial terms are a special case: in x + I(x^2), R does not know that I(x^2) builds on x, so type II and type III both test the linear term at x = 0, and both change with centering. It is usually better to test the polynomial as a whole, e.g. with poly(x, 2) (one test with 2 df), or by comparing models as in Section 3.1.2. poly() builds orthogonal polynomial terms whose coefficients are not directly interpretable, so use it for testing, and x + I(x^2) if you want to interpret the coefficients.

For categorical predictors, the same problem arises through the choice of contrasts. This is explained in Section 3.2.4.

3.2.3.1 Visualization of ANOVA fractions

Figure 3.1 gives an overview of the situation for 2 predictors A and B and their interaction. The upper left figure corresponds to the case where we have no collinearity between either of those variables. The figure on the top right (and similarly types I - III) are the three possible types of ANOVA for variables with collinearity. The “overlap” between the circles depicts the shared part, i.e. the variability that can be expressed by either variable (due to collinearity). Note that the shares in Type II, III do not add up to 1, as there is a kind of “dark variation” that we cannot securely add to either variable. Take the figure as a heuristic: it describes types I and II well, but type III sums of squares are not a partition of variance at all (the “overlaps” can even be negative). Type III is better understood as testing a particular hypothesis, as explained in Section 3.2.4.2.

3.2.3.2 General recommendations

Which type of ANOVA is most appropriate? Unfortunately, the answer is both “it depends on what you want to know” and “there is a lot of discussion about this topic”. I would say the following:

  • If you have an orthogonal, balanced design, type I and II are identical. Type III is identical as well but ONLY if categorical predictors use sum-to-zero contrasts (see Tip 2.1) and numeric predictors that are part of interactions or polynomial terms are centered (see Section 3.2.4.2).

  • If not, choose type II or type III ANOVA. Type I is really only appropriate in this case if you explicitly want to have the order-dependence (e.g. if you assume that one of the predictors always takes precedence for biological reasons).

  • To decide between II and III, note that type II can be read as a (partial) partition of the explained variance, at least in models without interactions, whereas type III sums of squares are better understood as tests of specific hypotheses (main effects at the reference level or the mean of the other predictors). The main question is how main effects should be tested when the model also contains an interaction. We look at this in detail for categorical predictors in Section 3.2.4. Decide before looking at the results, from your question and design, whether the model contains the interaction and whether you are interested in average or in conditional effects, and report the full model either way. Some general hints:

    • No interaction in the model: use type II (car::Anova(fit)). Without interactions, type II and III are identical anyway. Test polynomial terms as a whole, e.g. with poly(x, 2) (see Caution 3.1).

    • Interaction in the model: a main effect is now an average over an effect that varies, so ask yourself first if such an average is meaningful for your question. Often, it is more informative to describe the interaction directly, i.e. the effect of one predictor at different values of the other (simple effects; for numeric predictors, see Section 2.10.3; for factors, see Note 3.1). Judge the interaction by its estimated simple effects with confidence intervals, not by its p-value; if they differ strongly, point out that a main effect is only an average over them. If you do want main effects, both types are defensible:

      • Type II (the default of car::Anova()) tests main effects without the interaction, i.e. respecting the hierarchy of the model (marginality principle, Nelder, 1977). Variance shared between main effects and interaction stays with the main effects, so if the interaction is weak, type II is often the more powerful test. With a substantial interaction, however, the main effect is an average over the other predictor whose weights depend on the cell sizes (but are not simply proportional to them).
      • Type III tests main effects averaged with equal weights over the other predictor, a hypothesis that is independent of the design and remains meaningful if there is an interaction; if the interaction is in fact weak, it has somewhat less power than type II. It requires centered numeric predictors (Caution 3.1) and, for factors, sum-to-zero contrasts (Section 3.2.4).
      • Which of the two is preferable is debated (e.g. Shaw and Mitchell-Olds (1993) favour type III, Langsrud (2003) and Fox and Weisberg (2019) type II; see also Hector, Von Felten and Schmid (2010)); report which one you used. The test of the interaction itself is identical in both. Don’t remove an interaction only because it is not significant to simplify the ANOVA; this is a model selection step (see the chapter on model selection, in particular Section 8.3).

  • Note that for reasonably balanced and orthogonal data, as they occur in controlled experiments, type II and type III with sum-to-zero contrasts usually give nearly identical results. However, with stronger imbalance or collinearity together with an interaction, differences tend to get larger, even with correct coding and centering (type II then often, but not always, gives the larger F values), and partitioning can get fragile due to the large shared components. Such differences are not a sign of an error, but reflect that the two types test different hypotheses (see the example in Hector, Von Felten and Schmid, 2010). Note that collinearity is not restricted to numeric predictors: a factor can also be correlated with a numeric predictor (e.g. if some islands lie at higher elevations than others), with the same consequences for the order dependence of type I and the differences between type II and III. Check collinearity, e.g. with the correlation between predictors or, with more predictors, with variance inflation factors of the model without interactions (see Section 2.8; with interaction terms, vif() warns and the values are not meaningful), and center the predictors. Type II is robust to centering and coding, but a main effect is only interpretable as such if the interaction is weak; type III can differ considerably, in particular when predictors are skewed, correlated and interact. Don’t read a loss of significance as the loss of an effect, or shared fractions as causal importance, and put more emphasis on effect estimates with confidence intervals, on testing blocks of predictors by model comparison (Section 3.1.2), or on hierarchical partitioning (Lai, Zou, J. Zhang, et al., 2022; Lai, Zou, S. Zhang, et al., 2022).

  • Note also that, for many cases, there are good alternatives to ANOVA. ANOVA derives its popularity from its long history for balanced experimental designs, and its presence in every textbook. For unbalanced collinear observation data, however, standardized effect sizes, average marginal effects or marginal means (see Note 3.1) may be better choices.

3.2.4 Categorical predictors: contrasts influence ANOVA results

For categorical predictors, a complication occurs that is related, but not identical, to the issues discussed in Section 3.2.3: in case of collinearity, type I, II and III ANOVA can give very different answers (as before), but type III additionally depends on how the factors’ contrasts are coded (see Section 2.6.1). As this regularly causes confusion, let’s look at a typical example.

3.2.4.1 The problem

3.2.4.2 What is going on?

The key to understanding this is the following:

The coding of a factor never changes the fitted model. It only changes which hypotheses the individual coefficients and the type III tests examine.

We can confirm the first part of the statement by looking at the predictions of the two models, which are indeed identical:

all.equal(fitted(fit), fitted(fitSum))
[1] TRUE

This holds as long as the model contains all lower-order terms of each interaction. If you, e.g., remove a main effect but keep its interaction, or use uncorrelated random slopes in a mixed model (see Caution 4.2), the coding also changes the model itself.

For the second part, we have to consider what hypothesis / comparisons are expressed by the contrasts. In a model with interactions, every lower-order term (a main effect, or a two-way interaction in a model with a three-way interaction) is estimated and tested at the zero point of the variables it interacts with. This zero point is

  • for a treatment-coded factor (R default): the reference level
  • for a sum-to-zero coded factor (contr.sum, contr.helmert, contr.poly; see Tip 2.1): the unweighted average over its levels
  • for a numeric predictor: the value 0, or the centering value if the predictor was centered

Thus, with treatment contrasts, the “main effect” of grazing in the type III ANOVA is the effect of grazing in the control plots (the reference level of fertilizer), where grazing has hardly any effect. With sum-to-zero contrasts, it is the effect of grazing averaged equally over the three fertilizer treatments. Both tests are correct, they just answer different questions. Note that this is the same rule that you already know from the regression table: in summary(fit), the grazing estimate is the effect of grazing at the reference level of fertilizer. The same applies to the (Intercept) row of the type III table: with treatment contrasts, it tests if the mean of fenced control plots is zero, with sum-to-zero contrasts if the unweighted average over all treatment combinations is zero.

The following table summarizes which results are affected by the coding:

Result Depends on coding?
Predictions, residuals, R², AIC, likelihood ratio tests no
Type I and type II ANOVA no
Type III test of the highest-order interaction no
Type III test of terms that are part of an interaction yes
Individual coefficients and p-values in summary() yes
Results from emmeans() and joint_tests() (see Note 3.1) no

Thus, if you want type III tests of main effects that are averaged over the levels of the other factors, use sum-to-zero contrasts for all factors, and center all numeric predictors that are part of an interaction. Centering means subtracting the mean (or another meaningful value), e.g. dat$cx = dat$x - mean(dat$x) (see Section 2.10.3). Set the contrasts locally in the model call via contrasts = list(...), as we did for fitSum above.

You can also change contrasts globally via options(contrasts = c("contr.sum", "contr.poly")), but this silently changes the meaning of all coefficients in every model you fit afterwards (reset with options(contrasts = c("contr.treatment", "contr.poly"))). Note also that the coefficients of a sum-coded model (grazing1, fertilizer1, …) in summary() are deviations from the average over levels and are hard to read. Don’t report them, report estimated means instead (see Note 3.1).

What about type II? Type II (the default of car::Anova()) does not depend on the coding (grazing: F = 14.2, p = 0.0005), but in a model with an interaction, it tests grazing while ignoring the interaction. Roughly speaking, it averages the grazing effect over the fertilizer treatments with weights that depend on the number of plots per combination (but are not simply proportional to it). If the interaction is weak, this is the more powerful test; if it is strong, the result is harder to interpret. If the interaction matters, the effect of one factor at each level of the other (simple effects) is usually more informative than any main effect. Such simple effects, as well as comparisons between individual treatments, are best calculated with the emmeans package:

Note 3.1: The emmeans package

emmeans is not an ANOVA, but a general tool to interpret fitted models (lm, glm and mixed models), based on three ideas:

  1. Estimated marginal means: predicted means for each factor level or combination of levels, averaged over the other factors, with numeric predictors at their mean (unless specified otherwise). As model predictions, they don’t depend on how factors are coded.
  2. Equal weights: by default, all levels that are averaged over get the same weight, which corresponds to the main-effect hypotheses of a type III ANOVA with sum-to-zero contrasts (for alternatives, see below).
  3. Adjusted comparisons: differences between these means are tested as contrasts, adjusted for multiple testing, e.g. Tukey for all pairs, or Dunnett for comparisons against a control.

3.2.4.3 Practical recommendations for categorical predictors

The general recommendations in Section 3.2.3.2 also apply to categorical predictors. In addition, note the following:

  1. Reference level and contrasts: check the order of the factor levels before fitting, and set the reference level deliberately (see Section 3.2.4.1). With R’s default treatment contrasts, it determines what the coefficients in summary() refer to, and also what type III main-effect tests refer to. For a type III ANOVA, therefore set sum-to-zero contrasts locally, e.g. contrasts = list(fertilizer = contr.sum, grazing = contr.sum), and never interpret a type III ANOVA with treatment contrasts as main effects.
  2. Interactions between factors: judge them by the estimated differences between simple effects and their confidence intervals. The interaction test alone tells you neither where effects differ nor, if it is not significant, that they are equal. Separate tests within each group are no substitute: “significant in one group, not in the other” is not an interaction.
  3. Unequal group sizes: with sum-to-zero contrasts, type III weights all treatment combinations equally, which suits designed experiments where cell sizes differ by accident. The weights of type II depend on the cell sizes, but are not proportional to them, so type II does not give population-weighted averages either. If you want averages weighted by group sizes, e.g. in observational data where group sizes reflect the population, use emmeans with weights = "proportional" (Note 3.1).
  4. Small and empty cells: report the number of observations per treatment combination (table()), as combinations with very few observations (as a rough rule of thumb, fewer than about 5) give imprecise estimates, which show up as wide confidence intervals; this also makes the difference between type II and III less predictable. If a combination is empty, type III cannot be computed, and type II tests hypotheses that are hard to interpret; dropping the interaction instead assumes that the effects of the two factors add up.

Alternative: estimated marginal means. Many of these questions (simple effects, comparisons between individual treatments, the choice of weights, empty cells) can be answered more directly with the emmeans package, which may be the better choice, as its results do not depend on contrast coding (see Note 3.1).

For more complex models in general (mixed models, hierarchical models), reliably adjusting R2 components for complexity in an ANOVA is very complicated. I would recommend that

  • If you report raw components (which is the default in most papers), consider that this is a description of your model, not an inference about the true variance created by the respective factor, and include in your interpretation that variables or model components with more df will always tend to explain more variance

  • A possibility is to calculate variance explained via a cross-validation on a hold-out data. If a sensible cross-validation can be set up (which is not trivial if there are cluster / correlation structures in your data), this is a relatively stable metric of variance explained.

  • Alternatively, you could adjust R2 by a null expectation, similar to the parametric bootstrap for the LRT (Section 3.2.2). However, because you subtract what is expected under H0, this will be a conservative estimate.

3.3 Relationship between lm and other hypotheses tests

ANOVA is just one example of the close relationship between the lm and other null hypothesis significance tests. ANOVA can either be seen as a special test (traditional view), or as a special evaluation of a fitted lm (modern view). I would recommend taking the modern view, as it easily generalizes to GLMs and other more advanced regression models such as GLMMs.

It is interesting to consider more generally which hypothesis tests can be obtained by looking at certain results or tests on the linear model. As you can see in the table below, there are many classical hypothesis tests that are equivalently or nearly equivalently tested by a linear model.

Based on this, one could think it doesn’t matter then if we use a regression model or a hypothesis test. However, the advantage of the regression model is that

  • It provides a richer output

  • It provides the same output for all cases, with clear ideas about how to check residuals etc.

  • It allows us to adjust for the effects of covariates

3.4 Take-home messages

Tip
  1. An ANOVA is not a model but a test that is run on a fitted model: it asks how much the fit improves when a term is added, and whether this improvement is larger than expected if the term had no effect.
  2. With collinear or unbalanced data, the type I ANOVA depends on the order of the terms in the formula. Use type II if the model has no interaction; with interactions, think about which hypothesis you want to test. Report which type you used.
  3. The coding of a factor never changes the fitted model, but it changes type III tests of terms that are part of an interaction. With type III, use sum-to-zero contrasts and center numeric predictors in interactions, or use emmeans::joint_tests(), which does not depend on the coding.
  4. If the model has an interaction, describe the effect of one predictor at the levels (or values) of the other, with estimates and confidence intervals (emmeans). “Significant in one group, not significant in the other” is not evidence for an interaction; test the difference of the effects.
  5. Raw sums of squares and R2 fractions describe your fitted model, are not the true importance of a predictor, and are too high for terms with many df (e.g. a factor with many levels). For a simple lm use the adjusted R2; for more complex models report the raw fractions as a description only, or use cross-validation on hold-out data.
